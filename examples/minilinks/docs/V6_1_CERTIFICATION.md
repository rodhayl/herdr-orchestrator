### 2.3 Hardened Certification Guard (`assert_real_certifiable`)

Factory v6.1 enforces a centralized gatekeeper (`assert_real_certifiable`) implemented in [tools/factory.py](file:///root/agy-herdr-factory-poc/tools/factory.py) and invocable via `python3 tools/factory.py certify guard <run_id>`. A run is rejected if any of the following conditions are met:
1. `FACTORY_TEST_HARNESS=1` is active in the environment.
2. Manifest indicates `contains_mock_execution: true`.
3. Run or any individual task failed or timed out.
4. Any attempt's `execution_mode != "REAL"`.
5. Missing `real_evidence` bundle or missing `raw_result_hash`.
6. Resolved executable realpath is contained within test fixtures (`factory_tests`, `/tmp/`, `test_shims`).

## 3. Pillar 2: Harness Read-Only Authentication Discovery

### 3.1 Architecture & Non-Destructive Principles

The Factory v6.1 discovery subsystem provides zero-side-effect, non-destructive discovery of credentials across all 5 supported harnesses (`probe_harness_auth` and `probe_profile_auth`). It never initiates interactive logins, does not mutate user configuration files, and redacts secret tokens automatically across all logs and manifests (`redact_secrets`).

### 3.2 Discovery Matrix Across Harnesses

| Harness | Primary Inspection Mechanism | Fallback Inspection Mechanism | Discovered Auth Source | Runtime Status |
| :--- | :--- | :--- | :--- | :--- |
| **AGY** | `agy models` exit code & model listing | Shell command resolution | `provider_credentials` | **`AUTHENTICATED`** |
| **Droid** | `FACTORY_API_KEY` environment variable | `droid doctor` non-destructive output | `api_key_env` / `stored_oauth` | **`AUTHENTICATED`** (with key) / `AUTH_BLOCKED` |
| **Codex** | `OPENAI_API_KEY` environment variable | `codex login status` / `codex doctor --json` | `api_key_env` / `subscription_login` | **`AUTHENTICATED`** (with key) / `AUTH_BLOCKED` |
| **Claude Code** | `CLAUDE_CODE_TOKEN` / `ANTHROPIC_API_KEY` | `claude auth status --json` | `api_key_env` / `stored_oauth` | **`AUTHENTICATED`** (with key) / `AUTH_BLOCKED` |
| **OpenCode** | `OPENROUTER_API_KEY` environment variable | `opencode auth list` (stored `auth.json`) | `api_key_env` / `provider_credentials` | **`AUTHENTICATED`** (with key) / `local_free` |

### 3.3 Free Tier & Local Model Handling

For OpenCode profile `opencode-mimo-free` (`openrouter/openrouter/free`), the authentication probe classifies the provider as `local_free` (`authenticated: true`), allowing zero-cost real transport execution without requiring third-party API keys.

### 3.4 Auth-Aware Dynamic Fallback Routing

During task scheduling:
1. Tasks declare an semantic **Execution Class** (`routine`, `standard`, `deep`) and required capabilities (`coding`, `backend`, `frontend`, `testing`, etc.).
2. The deterministic router evaluates candidate profiles from [harness_profiles.json](file:///root/agy-herdr-factory-poc/harness_profiles.json).
3. Any profile flagged `AUTH_BLOCKED` by `probe_profile_auth` is cleanly skipped without throwing unhandled exceptions.
4. The router dispatches to the highest-ranking authenticated profile or halts gracefully if all capable profiles are unauthenticated.

## 4. Pillar 3: Real Multi-Harness Dispatch

### 4.1 Heterogeneous Engine Architecture

Factory v6.1 orchestrates across 5 distinct execution engines via standardized adapter boundaries:
* **AGY** (`AgyAdapter`): Orchestration, specification, integration, and audit workflows via `agy` CLI (`gemini-3.8-flash-high` and `claude-sonnet-4-6`).
* **Droid** (`DroidAdapter`): High-autonomy backend implementation and refactoring via `droid exec` (`qwen3.8-max`).
* **Codex** (`CodexAdapter`): Frontend engineering and client logic via `codex exec` (`gpt-5.6-luna`).
* **Claude Code** (`ClaudeAdapter`): Automated test generation and specification refinement via `claude -p` (`claude-sonnet-5`).
* **OpenCode** (`OpenCodeAdapter`): Modular support, mechanical modifications, and test fixtures via `opencode run` (`gemini-3.8-flash` / `mimo-v2.6-flash-free`).

### 4.2 Isolation & Containment Invariants

* **Isolated Git Worktrees**: Every attempt executes in a dedicated worktree under `.agy-factory/worktrees/<run_id>/<task_id>/att-<n>`. The orchestrator commits verified diffs; workers are prohibited from running `git commit`, `git push`, or modifying branches.
* **Herdr Workspace & Pane Isolation**: Attempts run inside dedicated Herdr terminal panes on protocol 22 with full resource accounting in `owned-resources.json`.
* **Path Allowlist Boundary**: Workers are restricted to designated path allowlists (`examples/minilinks/**` for implementation tasks, `examples/minilinks/docs/**` for specification tasks). Out-of-bounds writes trigger immediate attempt failure and abort.
* **Clean State Transitions**: Tasks follow deterministic state transitions: `PENDING` -> `READY` -> `DISPATCHING` -> `RUNNING` -> `RESULT_RECEIVED` -> `PATH_VALIDATED` -> `VALIDATING` -> `COMMITTED` -> `INTEGRATED` -> `COMPLETED`.
